# 用任务结果和实际读取成本验收默认规则精简

Status: accepted（2026-11-24）

精简默认规则时，用原版和候选版在可比较的条件下完成同一项代表性任务，再比较一项仍需用到相关约束的相邻任务。采纳精简的条件是两类任务都达到原有验收标准、能找到各自必需的项目约束，并且实际读取成本有可复验的下降。

例如，精简 Web 设计索引后，修复键盘焦点应能用更少的读取找到焦点移动和返回规则，修改组件主题仍应找到项目的对比度和设计 Token 约定。静态文件数和字节数可用来选择试验对象，实际读取轨迹用来验证节省了什么。[任务回放与读取量的验证方式](../../skills/ai-rulers-init/evals/README.md)

## 首批索引精简的适用范围

首批候选只在直接加载具体 Web 规则时，把内容与已核实的默认纯导航版本完全一致的索引缩为路径。索引照常参与校验和必读依赖解析。首次查找规则时需要阅读的索引、只选领域时给出的索引，以及主动请求查看的索引，都提供全文。

通过原有校验后，项目已采纳的定制索引、含有独立约束的索引、无法确认是默认纯导航版本的索引，均提供全文。这样即使项目只改了一行导航文字，也能读到团队审阅过的内容。文件名相同不足以判断用途，例如交付索引还说明了规则准备状态的适用边界。[交付索引](../../skills/ai-rulers-init/templates/runtime/domains/delivery/INDEX.md)
